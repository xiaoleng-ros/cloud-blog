## 出发点

以前一次联调要开三个进程：代理、后台、前台。冷启动两分钟，改一行样式还要分辨请求打到哪一路。现在默认只开前台。

## 代价是什么

| 能力 | 单前台 | 需要后台 |
| --- | --- | --- |
| 排版、样式、交互 | ✅ | — |
| 真实文章内容 | ❌ | ✅ |
| 评论区读写 | ❌ | ✅ + 代理 |
| 后台数据变更推送 | ❌ | ✅ + 代理 |

判断标准很简单：**要看 `/api/*` 的结果，才值得多起一个进程**。

## 代理什么时候上

只在验证同源请求时。浏览器直接调后台是跨站请求，会撞上 Origin 全等校验；经代理后 `/api` 变成同源相对路径。但代理会重写 Host，后台的写操作反而会被判成跨站，所以写操作仍然要在后台端口直连做。

```bash
npm run dev:blog    # 只调 UI
npm run dev:proxy   # 验 /api/* 链路
```
