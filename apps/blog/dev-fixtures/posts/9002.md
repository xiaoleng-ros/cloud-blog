## 问题从哪来

同一段提示词，上午和下午给的东西不一样。做 demo 时无所谓，一旦结果要进代码库，"不一样"就是事故。

## 我的三条规矩

- **输入固定**：模型版本、温度、外部资料快照，全部写进产物头部注释。
- **输出加指纹**：对正文做一次哈希，改动前先看哈希对不对得上。
- **失败要吵**：拿不到指纹就中止，不要退回"差不多"的版本。

```js
const stamp = createHash('sha256').update(body).digest('hex').slice(0, 12);
if (!body.includes(stamp)) throw new Error('结果与指纹不匹配，拒绝写入');
```

## 一个反例

曾经我把"探测失败"当成"没有变化"，结果缓存永远停在旧内容上，改了三轮才反应过来：**探测和落库必须分开，只有全量成功才允许推进指纹**。

> 把随机性挡在流程外，比事后调参便宜得多。
