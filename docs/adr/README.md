# 架构决策记录（ADR）

这个目录记录**「为什么这么做」**，不是「怎么做」。用法与约定：

- 命名：`NNNN-短横线小写标题.md`，编号连续递增，不复用、不删除。
- 状态：`提议` → `已采纳` → `已废弃` / `被 NNNN 取代`。废弃的不要删，保留历史。
- 一份 ADR 只回答一件事：当时面临什么约束、考虑过哪些方案、为什么选了这一个、代价是什么。
- 代码注释解释**局部**（这个函数为什么这样写）；ADR 解释**跨模块的取舍**（为什么全站这样组织）。
  两者不重复：注释细节改了不会影响结论，ADR 结论改了要新开一份。

## 为什么单独存在这个目录

`.gitignore` 里 `**/*-plan.md`、`**/*方案*.md` 等通配把 `docs/` 整体排除在版本控制之外，
理由是「个人工作笔记不该入库」。这条规则对草稿是对的，但它连带排除了一类不该丢的内容：
**踩过坑之后得到的、用代码注释表达不了的架构约束**。

典型例子：本项目曾经「只改 `Cache-Control` 想让 HTML 进 CDN」，实测无效后才改用构建期静态化。
如果这条只活在一次性的方案文档里，半年后有人重新提「加个 s-maxage 不就好了」，
就会再花一次机会成本验证同样的事。ADR 的作用是把这类结论固化成可检索的档案。

因此 `.gitignore` 对 `docs/adr/**` 开了白名单，其余 `docs/` 仍不入库。
